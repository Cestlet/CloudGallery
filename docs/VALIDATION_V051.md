# CloudGallery 0.5.1 启动与浏览恢复

## 改动

- 启动保留 Android 启动窗口，异步恢复授权、所选目录、Room 索引和废纸篓过滤后才绘制页面，避免先显示空图库与连接提示。启动不等待远端扫描或图片下载。
- 最多对当前浏览锚点附近 15 张已缓存缩略图进行解码预热，每组 3 张，总等待上限 300 ms；图库与预热使用相同的 Coil 内存键，关闭图片交叉淡入。
- 从 Room 扫描状态读取上次成功时间，60 秒内重启不重复扫描。手动同步绕过该限制。
- 已有照片时，自动扫描不显示顶栏进度、不改变同步按钮和照片区域高度；失败保留本地内容，避免启动出现网络错误提示。手动同步与首次无索引的扫描仍显示进度和错误。
- Room 更新转成实际展示数据后去重，扫描轮次字段变化不触发相同照片列表的重复发布。
- 网格、瀑布流、列表分别按图库来源与相册保存首项锚点和像素偏移。滚动时定期保存，页面离开及进入后台时补存。新增照片时优先恢复锚点，锚点消失时限制在有效范围。
- 本机保存已知图片比例，瀑布流重启时直接采用已知比例，减少重新解码后卡片高度变化。

## 验证

- real/mock Debug 构建成功；26 项单元测试全部通过。
- 新增覆盖：持久化扫描时间的间隔边界、系统时钟回退、新照片插入后恢复原照片、已删锚点与缩短/空图库的有效位置处理。
- lint 0 错误、12 条既有提示。
- API 28 模拟器，202 张照片：确认进程已被 force-stop 终止后重启，网格、瀑布流、列表恢复相同首张可见照片；每次重启目录请求增量 0、图片请求增量 0。
- 已缓存照片恢复后没有“正在同步”“等待连接”提示。测试期间无 AndroidRuntime 崩溃。
- 关闭模拟服务并移除 adb 端口转发后，再次确认进程终止并冷启动：202 张照片索引与已缓存图片正常显示，没有连接或同步错误干扰页面。
- UI 捕获工具对空根节点做重试，不使用过期截图层级作为验证结果。

截图位于被忽略的 `app/build/tmp/settings/resume-grid.png`、`resume-waterfall.png`、`resume-list.png`。

## 限制

冷启动仍需系统创建进程、打开数据库和解码图片；本轮解决空图库闪动、重复扫描、进度条挤动及浏览位置丢失，不承诺冷启动耗时为零。未缓存、被系统回收或主动清除的图片仍需下载。未曾解码过的图片尚无已知比例。新账号、首次选择目录或没有索引时仍需首次扫描。26 项测试中的备份覆盖仍为本机模拟接口，真实上传限制沿用 0.5.0 说明。
