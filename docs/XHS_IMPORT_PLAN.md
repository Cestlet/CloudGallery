## 真机验证顺序

1. 连接已安装小红书的手机，记录手机型号、系统版本、小红书版本。测试账号由用户在小红书中登录，无需提供密码或令牌。
2. 检查普通多图帖子和图片查看页的无障碍节点，确认页码、可见图片区域、帖子标识或链接是否可获取。只保留去除个人内容的结构样本。
3. 接入最小诊断服务，由用户主动启用。验证上下音量键顺序、250ms 窗口、长按重复、单键调音量、系统快捷键和其他服务冲突。
4. 验证可以从允许访问的图片来源取得当前图片文件；节点里的 ImageView 或页码不能单独证明原图地址可获取。遇到登录限制或不可获取来源则记录失败，不绕过限制。
5. 将结果归为：原图与页码均可靠、只能取得图片列表、只能取得屏幕区域、无法可靠识别。后两种不得当作原图导入完成；截图替代需要用户另行决定。

## 可行后实施

- 快速导图默认关闭，首次提供用途说明并引导系统授权；不逐次弹出导入确认。

## 公开图片来源实测

使用当前帖子主动复制的分享链接，在电脑上以普通移动浏览器 User-Agent 请求公开移动页面。没有读取小红书 Cookie、令牌、私有缓存或生成接口签名。

- 桌面请求转到登录页；移动 `/discovery/item/<noteId>` 返回 200，HTML 的 `window.__SETUP_SERVER_STATE__` 包含 `LAUNCHER_SSR_STORE_PAGE_DATA.noteData.imageList`。
- 网页提供的 H5_DTL 图片是 1080 宽预览。7 图帖第 2 张的预览实测 1080×1461，带有“小红书”水印。
- 页面提供 `fileId`。以公开 ci CDN 的文件路径请求，两个样本均返回 200：7 图帖第 2 张 PNG，2838×3840，19401834 字节；另一个单图帖 JPEG，6000×3368，6495654 字节。尺寸均与笔记元数据一致；第 2 张高清图目视未见预览上的平台水印。不能仅凭尺寸证明文件与作者上传的二进制完全相同。
- App 中从第 1 张滑到第 2 张后，节点变为“图片,第2张,共7张”；网页列表的第 2 张与当前画面目视一致。
- 图片路径规则是未文档化的公开 CDN 行为，仅证明本轮两个样本可用，不承诺所有笔记或未来版本兼容。文件必须按实际格式保存，不追加强制 PNG 转换参数。
- 已加入 `tools/xhs-source-probe.py` 可重复研究。校验来源域名、最终帖子 ID、图片总数及页码；登录页/非图文帖失败；JSON 解析不执行远程脚本；下载设置超时及大小上限。`--source-file` 研究公开文件路径，默认仅下载页面提供的预览。
- 输出位于忽略的 app/build/tmp/xhs-source，不打包进 APK；报告不包含分享签名参数或用户会话。

参考：[公开项目的 CDN 路径实测记录](https://github.com/qsniyg/maxurl/issues/1543)。本项目没有复制该项目实现。

## 当前帖子识别仍待验证

UiAutomator 可见节点没有 URL 或帖子 ID，不能保证“按键时自动知道当前帖子”。用旧剪贴板链接配合新页面的页码可能误存其他帖子的图片，因此不能直接作为无感方案交付。

已在 mock flavor 增加 XhsSourceProbeService，real flavor 不包含该服务。诊断仅记录节点数量、图片页码、附加数据键名、明确暴露的帖子 ID、URL 主机及按键计数；不记录帖子正文或附加数据任意值，不点击、读取剪贴板、截图、下载或上传。诊断构建已通过，安装在模拟版。

用户已主动启用诊断服务，完成实测：

- 当前另一个 8 图帖，节点页码由第 1 张更新至第 4 张。72 个节点未暴露帖子 ID 或 URL；附加数据仅观察到 STATE_DESCRIPTION_KEY 和 DATA_TEXT_CHARACTER_LOCATION_KEY。
- `serviceInfo.flags` 显式设置为 112，包括读取交互窗口、报告视图 ID、请求按键过滤；音量浮层不作为前台应用切换处理。
- 普通 adb input / UiAutomation 注入没有进入本机服务按键回调，不能据此断定按键过滤不可用。改为该模拟器公开音量输入设备 gpio 的事件流后，4 个按下/抬起事件被接收，识别为 1 次组合。
- `tools/probe-xhs-keys.py` 重复验证通过：先上后下、先下后上均一次触发；长按 650ms 不重复触发；间隔 400ms 不触发。该脚本仅是模拟器诊断，不是正式版对 root/ADB 的依赖，物理手机仍需验证。
- 删除了不适合验证这一输入路径的临时 Android instrumentation 测试源码；正式版未加入诊断服务。
- 最终诊断模拟版构建通过；lintMockDebug 为 0 错误、2 项警告。

当前结论：已知分享链接时，公开移动页可提供图片列表，公开 CDN 高清文件及当前页码对应已验证；无菜单自动获取当前帖子的链接仍未解决。不得把这部分验证描述为完整无感导图已完成，也不得用旧剪贴板链接未经确认地匹配当前图片。

后续接入需要可靠的当前帖子来源。若只能依赖用户复制链接，必须将流程明确为“先复制帖子链接，再按双音量键选择当前图片”，并处理跨帖子误匹配；这与最初全程无需菜单的目标有差异。
