# 0.3.2 原图修复与布局验证

## 原图加载

复现详情页“图片加载失败（HTTP 403）”。原实现取得 filemetas 的 dlink 后直接下载，缺少原图下载需要的 access_token。补上当前令牌，保留原有签名参数，避免重复旧令牌；继续发送 User-Agent: pan.baidu.com。发送令牌前检查初始下载域名属于百度，模拟 HTTP 下载仅用于本机注入服务。

接口说明参考：[百度关于下载 403 的答复](https://cloud.baidu.com/ask/141)。

覆盖安装到 API 28 模拟器后，两个真实原图已成功下载并缓存，详情页没有 HTTP 403 或解码失败。首张读取到有效 JPEG，6000×3368 像素、9,521,368 字节。只记录格式和尺寸，不保存真实图片截图、目录名称或带令牌的链接到文档。

## 浏览布局

- 网格：固定方形缩略图，按日期分组。
- 瀑布流：使用 LazyVerticalStaggeredGrid，日期标题跨列，图片按解码后的实际缩略图比例展示；比例尚未获得时使用方形占位。
- 列表：每行展示缩略图、文件名、目录和日期，整行可打开详情。
- 三种布局共用当前相册、缓存和可见区域预取逻辑。照片页及相册内都有切换入口。
- SharedPreferences 保存布局，重启恢复，不影响网盘授权和目录选择。

真实图库手动验证：网格切到瀑布流后，已加载首屏图片以 660×370 的比例显示；切到列表可见文件名和日期，点击列表图片成功加载原图。强制停止重启后仍选中列表。未把相同拍摄比例的图片人为赋予不同高度。
