# 0.3.1 缩略图加载优化

## 发现

真实图库已索引 806 张照片。旧版保存的百度缩略图地址请求 size=c850_u580；网格只显示较小图片，却下载较大变体。附近预取串行执行，窗口变化时取消整批任务，返回缓存图片也先进入空加载状态。缓存提交时会反复枚举和排序磁盘文件，缓存键生成逐字节使用字符串格式化。

## 修改

- 百度目录返回多个缩略图时，网格按 url2 → url1 → url3 选择；实际更新后的 806 条记录请求 size=c360_u270。已有缓存继续复用。
- 按滑动方向预取附近 24 张，任务按图片和版本保留，移出窗口才取消。包含可见区域的重叠任务，避免反复重启下载。
- 可见缩略图 6 路，附近预取 2 路，后台缓存 1 路，原图 2 路，各自限流；排队的预取不会提前占用图片锁，可见请求能先取得该图片的下载名额。
- 同一缓存键的请求合并；下载通过可取消的 OkHttp Call，等待响应头或读取慢响应时都能取消。
- 首次组成图片组件时即可取得缓存文件，Coil 可直接显示已有内存/磁盘内容。
- SHA-256 文件命名格式保持兼容，改用直接十六进制转换。缓存空间不足时批量回收，避免每次下载都扫描整个缓存目录。
- 完整扫描后，WorkManager 在非计费网络、电量充足时缓存最近最多 1000 张缩略图。只读取选定数据源；目录或账号切换后停止旧范围任务，不批量下载原图。

## 验证

真实版和模拟版构建通过，Android lint 未发现错误。22 个 JVM 测试通过，包括百度缩略图变体选择、12 个并发读取只发出 1 次请求、取消等待响应头的请求、超限响应拒绝以及缓存键兼容性。

覆盖安装到 API 28 模拟器，真实授权和 806 条索引保留，自动扫描完成，可见页面未出现图片加载错误。后台缓存工作实际处于 RUNNING；检查时已有 623 / 806 张真实缩略图对应的本地文件，之后继续缓存。只记录汇总数量，不保存真实账户目录名称、图片内容或带授权参数的 URL 到文档。

没有同设备旧 APK 的完整首屏/滑动时间对照，不能据此宣称快几倍或保证完全无等待。已缓存内容能减少网络等待，首次未缓存内容仍受百度 CDN 和网络影响。缓存上限 256 MB，不保证整个大型图库永久离线；十万张数据库分页、过期缩略图恢复、原图性能仍需后续工作。
